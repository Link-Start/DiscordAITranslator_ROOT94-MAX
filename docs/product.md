# 功能与行为说明

<a id="purpose"></a>

## 用途

DiscordAITranslator 翻译发送和收到的消息、回复预览、受支持的嵌入内容，以及已启用的论坛/讨论串标题，同时保留 Discord 标记和用户原文。

普通用户无需理解供应商 API 或仓库内部实现。常用频道操作应放在 Discord 消息输入框旁，高级默认值和凭证放在 BetterDiscord 设置中。

<a id="current-channel-interaction"></a>

## 当前频道的操作

- 左键点击翻译图标，打开当前频道翻译设置。
- 右键点击翻译图标，只切换当前频道的自动翻译。
- 关闭频道翻译时，取消该频道待处理的自动收发翻译，并恢复当前显示的收到消息译文、回复预览、嵌入内容和讨论串标题，包括之前手动触发的译文。
- 关闭频道后保留有效翻译缓存和发送消息的原文/编辑元数据，仍可手动翻译。
- 插件正常停止时，会在关闭前提交一次尚未落盘的防抖缓存写入；只保存内存中已确认的缓存，不启动新翻译。
- 一个频道的状态不得改变其他频道或全局备用供应商。

<a id="approved-channel-popout"></a>

## 频道弹窗的职责

频道弹窗包含：

- 当前频道的主翻译供应商
- 恢复跟随全局设置的操作
- 语言识别助手
- 收到消息的输入语言
- 收到消息的输出语言
- 发送消息的输入语言
- 发送消息的输出语言
- 既有的频道、服务器和全局语言作用范围锁

频道弹窗不包含：

- 自动翻译开关
- 只读状态说明
- 备用供应商
- API 密钥、端点或模型字段
- 全局显示或自动化默认值

<a id="approved-global-behavior"></a>

## 全局行为约定

- 没有明确记录的频道，默认关闭自动翻译。
- 当前频道图标的右键操作是面向用户的唯一自动翻译开关。
- 配置迁移必须保留既有的明确频道记录。
- 输入框翻译按钮和消息操作栏翻译按钮始终可用，不作为可关闭的设置。
- 备用供应商及供应商凭证保持全局归属。

<a id="translation-quality"></a>

## 翻译质量

- 短外语单词和简短口语也应能够翻译。
- 不能仅因文本短就让 AI 判定跳过。
- URL、提及、Discord 标记、代码、命令、ID、模型名、产品名、配置的术语和受保护占位符不能被破坏。
- 专业术语没有公认的目标语言译法时保留原文；存在官方或广泛接受的本地化名称时可以使用。
- 输出只包含译文，不附解释或评论。
- Google Free 按编码后的请求长度无损拆分长文本，并用可逆的供应商专用传输形式携带保护占位符。全部分块和保护片段通过后才显示合并译文；部分返回或保护结构损坏的响应不能被当作完整结果显示。
- 转发消息使用可见快照正文作为原文。自动与手动翻译均绘制在转发框内，可选原文只组合一次；取消翻译或关闭频道时恢复同一快照正文，不修改 Discord 存储的原始记录。

<a id="validation-and-experimental-policies"></a>

### 校验与实验策略

结果按整条消息接受：可确认的名称、产品名和简称允许保留；普通片段校验失败时使用既有有界修复，耗尽后整条保留原文，不把成功片段拼成“部分翻译”。混合语言中的简称由 AI 结合原句明确选择保留，不能仅凭长度或大小写跳过。纯名称的既有兼容判定仍有误判风险；本地结构和语言检查不能证明语义正确。

经完整校验确认整条无需改动时，收到消息按正常跳过完成，移出失败重试列表，不写入译文缓存。完全保留原文的正文使用 Discord 普通消息样式，不显示“已保留原文”提示，也不添加译文颜色、色条或背景。通过整条校验且正文实际变化的结果使用已配置的译文样式和“已翻译”标记；正常保留名称不等于翻译失败，不另设“部分翻译”标记。原文引用或剧透附加内容不参与正文是否变化的判断。

typed AI 翻译在既有批次内参考消息语境：混合语言消息补充一份经过保护的完整原句，模型只翻译请求片段。同批消息用于判断术语与语气，当前句优先，不把无关消息硬接成对话；不扫描频道历史、不等待凑批、不增加预判或复审请求。短词和俚语仍交给模型理解。语境受预算限制，超限时省略；受影响的旧混合语言缓存和旧跳过判断重新计算，无关纯外语付费缓存继续兼容。设计理由见[批内语境与整条结果](../.agents/notes/implemented/bug-fix/2026-09-17-batch-context-whole-result.md)。

W4 单正文和 W5 整体标记历史批次候选方案默认关闭，需要明确、有界的内存授权。仅编译的影子结果不能授权网络调用。缓存身份、预算及被否决路线的边界见[实验授权笔记](../.agents/notes/implemented/architecture/2026-09-17-bounded-experiment-grants.md)和[校验边界笔记](../.agents/notes/implemented/architecture/2026-09-17-validation-and-repair-boundaries.md)。离线结构检查不能证明语义质量、持续提速或客户端显示正确。

<a id="live-and-historical-messages"></a>

## 实时消息与历史消息

- `new_only` 范围在首次遍历消息流前，先冻结当前频道最后一条消息 ID 作为会话边界。边界内的历史行即使延迟挂载或首次渲染为空后才出现，也不会进入实时队列；边界后的新消息即使在首次遍历时出现，仍可翻译。频道模型与消息流都无法提供基线时，保持未初始化，不接受空边界。该范围没有历史任务，因此不显示历史翻译胶囊。
- 实时消息走独立高优先级路径。第一条新消息立即提交，不等待固定封批延迟；请求返回后尽快显示译文。
- 实时请求等待期间显示固定大小的加载图标。同一事件循环内到达的消息可以合用请求，但运行时不会为了凑批而等待。
- 历史任务优先级较低，不得让实时消息等待整个历史任务完成。供应商允许并发时，可同时运行一个实时请求和一个历史请求；不允许时可等待在途请求完成，但下一个可用请求名额必须优先给实时消息。
- 历史采集合并已渲染消息和 Discord 消息缓存，按消息 ID 去重、从新到旧排序，最多选择配置数量的合格消息。
- 已渲染和已缓存的合格消息不足时，首次已加载消息扫描最多发起一次有界后台预取，补充缺少的数量。因此任务可能低于配置上限；不模拟滚动，不将预取结果注入可见列表，也不自动继续翻页。
- 历史数量配置是上限。进度以实际不可变任务大小为准：50 条合格消息显示 `/50`，只有 20 条可用合格消息时显示 `/20`。
- 已加载消息形成按频道隔离、以消息 ID 为键的不可变任务。已校验的主请求块可以分别通过原子显示事务变为可见，其余慢块或有界修复仍可等待；不能只提交一条消息的一部分。整个任务只最终结算一次。后续同级块遇到全局供应商故障时，已接受的当前结果仍保留，新派发和未接受结果继续服从该故障。默认关闭的整体标记批次候选方案只接收每条消息都恰好含一个完整 D 范围的原始批次；存在多范围消息时，整个原批次在消耗授权或派发前保留在 typed 路径。获准输入/输出使用严格的扁平 JSON 对象和完整消息提示词，允许完整且已校验的供应商块先于慢块显示。W5 块内部必须先完成有界修复，不能显示部分消息或未解决的块。原有原文/授权检查继续约束未接受工作；之后授权过期或撤销，不撤回已接受显示，但每条消息的原文失效规则仍然生效。
- 虚拟化消息行的历史结果只存储，不重绘整个聊天区；这些行之后挂载时读取最终存储状态。
- 输出语言选择器只包含明确语言。已退役的 `$discord` 别名不再出现在收发输出设置中；旧存储值一次性转换为客户端当前的具体语言，之后客户端语言变化不能暗中改写翻译目标。
- 收到消息的有效目标语言变化时，先停用旧配置下显示的译文，在下次原文采集前恢复不可变原文，并让该消息最多进入一次替代判断。旧目标语言译文不能成为新原文或反复生成历史任务。
- 用户输入时，已完成译文仍应显示。用户正在上滚阅读历史时，先立即存储已确认结果，等滚动手势空闲再重绘，延后有界且小于一秒。重建触发的滚动恢复若落在手势中途，会造成回弹感（2026-08-19 观察）；位于底部的实时视图始终及时显示。
- 阅读历史时开启自动翻译，应保持当前阅读区域和视线所在消息。近期手动翻译锁只属于该消息自己的事务，不能把频道开启操作引向旧位置。当前可见锚点提供一次 Store 投影刷新；即时和稳定后的视口恢复均受用户滚动意图序列保护，不重新挂载输入框组件（Composer）。
- 一次历史显示事务一起刷新该批次已挂载的消息行，并统一保护一次视口锚点；用户在显示期间改变滚动意图时，不能强行拉回。虚拟化消息挂载时读取最终存储状态。
- 一次历史显示事务先提交整批结果，再通过 Store dispatcher 只更新其中已挂载的普通消息和回复预览宿主行。正文和预览分别携带 DOM 修订；确认失败时只做有界定向重试，不能扩大为重建整个聊天区。纯虚拟化消息挂载后读取存储状态。频道开启和主引擎变化使用一次带锚点的 Store 投影刷新；插件启动/停止和设置重新初始化仍属于独立生命周期工作。
- 紧凑历史状态胶囊显示翻译图标和累计比例，只在未完成时附本轮用时，例如 `20/50 8s`。成功完成后只显示 `50/50`，不带秒数（包括 `0s`）。主文本不显示失败数或待显示数；详细信息放在悬停说明和重试操作中。是否就绪遵循下面的显示规则，不仅看供应商或存储是否完成。
- 补翻扫描完成且没有待翻内容时，只显示累计比例（空会话为 `0/0`），悬停说明显示“没有待处理消息”。空扫描和仅缓存完成不保留 `0s` 后缀，也不开启新计时轮次。
- 胶囊对当前频道使用统一累计比例：分子为已可显示的唯一译文，分母为这些 ID 加上全部排队、运行、可重试及待显示消息。从 `235/235` 上滚加载九条新消息后变成 `235/244`，完成后为 `244/244`；迟到回调不能把它替换成单批比例。重叠重试和重复 ID 只计一次。被滚动/设置刷新门阻挡的存储结果，在得到渲染结果前仍为待显示；已确认渲染，或确实处于屏外且可随挂载显示的结果，才计为就绪。重试耗尽或显示失败持续作为显示失败保留，直到当前修订成功或被判失效。仅供应商工作完成不能让胶囊宣告结束。
- 累计 ID 包含实时和历史显示 Store 的提交；待显示 ID 不进入就绪分子。普通批次重启和重新进入频道保留计数。全局跟踪重置清除所有频道；有效接收翻译配置变化只为受影响频道开启新的累计会话。完成状态持续显示且不自动隐藏，只显示比例。计时属于当前工作轮次，不属于整个累计会话，不累加空闲时间和旧轮次。悬停说明解释累计就绪、排队/请求/修复/提交/显示阶段、跳过项，以及相互独立的翻译失败和显示失败。
- 状态图标使用当前 Discord 主题：收集、排队、翻译、提交或待显示时为品牌色；完成为成功色；修复为警告色；终态部分失败为危险色。重试按钮将保留的翻译失败交给原有策略，将显示失败交给定向重绘调度器复用已存译文。手动显示重试只开启一个有界显示轮次；等待期间重复点击不会再次排队。显示恢复不新增翻译请求，也不扩大自动重试预算。有错误或待显示项时保留累计工作用时，工作停止后冻结，重试或新工作开始新时间区间；同一活动区间内阶段变化不重置时钟。
- 状态更新不得重绘消息列表。
- 历史加载图标跟随当前任务项的等待状态，不依赖直到最终结算才清除的队列标记。失败、跳过或取消的工作不能持续旋转。关闭翻译时，即使历史消息的显示记录尚无结果/来源，也要把已采集历史行纳入既有频道恢复事务；无关空闲行保持不变。
- 普通批次失败继续使用原有有界修复策略，不能悄悄丢弃。W5 候选方案只修复可归因到消息/范围 ID 的失败；根容器无效时终止受影响块，不按猜测映射显示，也不启动无界回退链。
- 历史项耗尽修复后留在频道重试账本。自动渲染或虚拟化扫描不重新收录它；只有明确重试、真实原文编辑或有效配置变化，才可为该消息建立新工作。
- 每条待处理消息使用固定大小的 CSS 加载图标，不依赖计时器驱动 React 重渲染。
- 译文始终附带类似 Discord“已编辑”标记的小型行内水印；悬停显示源语言/目标语言信息，它不是用户设置项。
- 收到消息只有一个原文控制。开启后使用既有行内引用或剧透形式，让原文与译文并存；没有第二种直接原文显示模式。
- 关闭自动翻译时，通过一个频道级显示事务恢复自动和手动译文、回复预览、嵌入内容及标题，不再补一次宽范围重绘。

<a id="message-lifecycle"></a>

## 消息生命周期

- 编辑已翻译的发送消息时，必须打开可编辑原文，并保存正确翻译后的替换内容。
- 其他用户编辑收到的消息时，必须使旧缓存和显示数据失效，再翻译新内容。
- 停止或卸载插件时，必须恢复消息、回复和嵌入内容的原文。
- 重载插件不能复用上一个运行会话留下的过期显示状态。

<a id="providers-and-detection"></a>

## 翻译服务与语言识别

- 内置官方 OpenAI 适配器使用 Responses API。
- 内置 Gemini 使用原生 `generateContent` API；自定义供应商即使使用 Gemini 模型，也服从其配置/识别出的适配器。
- 第三方及自托管服务使用独立的 OpenAI 兼容供应商，需要明确端点和模型。
- Google Free 无需密钥；官方 Google API 密钥归属 Google Cloud Translation。
- 全局语言识别支持本地优先并回退 Google、仅 Google、仅本地三种策略。

<a id="forum-and-thread-titles"></a>

## 论坛与讨论串标题

- 标题翻译服从当前讨论串或论坛帖频道配置。
- 只替换渲染出的标题文本，不能修改 Discord 频道 Store 对象。
- 标题编辑后使旧译文失效。
- 关闭频道或停止插件时恢复原始标题，并拒绝迟到回调。
