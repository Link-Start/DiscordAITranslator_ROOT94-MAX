# Agent Note: 日常设置与排障证据分层

Status: implemented

## Problem

高级页把并发控制、重置统计和缓存清理放在同一区域；维护标题的外边距叠加卡片间距，形成明显空白。诊断页把日常耗时、实验验收、底层资源和版本身份混排，普通使用者难以区分故障与样本不足。翻译缓存固定 500 条，也无法满足不同历史阅读量。

## Decision

日常界面只保留有明确使用目的的操作，当前行为归属[设置说明](../../../../docs/settings.md)。移除两个重置按钮，保留底层排障接口；缓存容量和清除操作组成独立卡片。容量规则由小型设置模块统一验证，缓存模块负责按时间淘汰，接线模块读取全局设置，不在运行时门面增加业务逻辑。

诊断摘要只呈现最近翻译、等待和异常；客户端环境与请求统计放进一个折叠区。实验达标判断与资源计数仍进入脱敏复制报告，不再作为普通界面指标。顶部保留面向用户的版本号，构建号作为排障身份移入折叠详情，复制报告继续保留二者。

此前将 Google Cloud 模型编辑收进高级设置的布局决定已由[模型直接配置笔记](2026-09-17-cloud-translation-model-row.md)替代；保留已有模型值的兼容约束继续成立。本文的缓存与诊断分层决定仍有效。

## Alternatives considered

- 完全删除技术统计：会丢失性能与资源泄漏排障证据，因此只收敛展示入口。
- 保留所有维护按钮并补充说明：无法消除低频操作的干扰，因此保留缓存清除，排障重置继续通过已有接口处理。
- 任意大小或无限缓存：会失去文件大小边界；采用 100～10,000 条、默认 500，并保持独立实验分区的既有容量。
- 删除 Google Cloud 模型配置并强制 NMT：会丢失已有覆盖值，也妨碍使用官方支持的其他模型，因此保留编辑能力；入口布局按上述后继笔记维护。

## Consequences

旧配置和非法配置保持 500 条默认。缩容会永久淘汰最旧记录，扩容不能找回它们，因此界面明确说明。更改容量不触发付费请求，也不重置并发或延迟统计。

缓存容量、加载、缩容、输入验证与简化后的诊断信息有合成回归。独立渲染可以核对间距和换行，不能替代 Discord 客户端的加载、主题与交互验收。版本定为 1.0.0，公开发布和客户端验证仍分别确认。
