# Agent Note: 用批内原句语境判断名称，按整条消息接受结果

Status: implemented

## Problem

按文字体系拆分的请求会把混合句里的简称孤立成普通单词，造成误译或无意义修复。旧 P3 在修复后保留未通过校验的片段，可能把半条成功结果显示为译文。用户已明确要求整条处理，并希望在既有批次内理解语境而不扫描整个频道。

## Decision

typed 消息在预算内附带一份经保护的完整原句。模型参考同批术语和语气，但当前句优先，无关消息不能相互补写。最初只向混合句中的单词候选开放显式保留，遗漏了多词名称、版本与百分比；这一许可范围已由[显式名称决定与正常跳过](2026-09-17-confirmed-name-skip.md)替代。正常词汇与俚语仍需翻译，修复仍只请求失败片段。

失败片段耗尽既有预算后，整条不作为成功译文提交。名称正常保留不算失败。完全不变的正文不着译文颜色，也不显示原文水印；实际变化且通过整条校验的正文显示“已翻译”。这替代了[先前软校验笔记](../architecture/2026-09-17-validation-and-repair-boundaries.md)中自动保留失败片段的规则，保留其身份归因、硬校验及语义限制。

缓存迁移覆盖混合文字、嵌入字段及语境超限的消息，避免旧结果绕过新策略。无关纯外语付费缓存继续兼容。当前接口和行为分别维护在[供应商说明](../../../../docs/providers.md)和[功能说明](../../../../docs/product.md)。

## Alternatives considered

未采用按短词或相邻目标文字直接跳过的规则：它无法区分简称与普通词。未增加全频道扫描、额外 AI 预判、二次校对或等待凑批：会扩大延迟、成本和无关语境影响。保护词仍由现有本地机制精确恢复，不把真实保护内容重新发给模型。

## Consequences

模型获得原句信息，新增语境受到既有字符、字节和 token 预算限制。输入量仍会增加；普通失败不再被提前放行，可能走完原有修复次数。纯名称兼容启发式和模型语义理解仍有误判风险，不能用结构校验通过或少量样本宣称零误译。

合成回归覆盖短词、名称的标点/格式、修复中的候选许可、普通指令拒绝、保护遮蔽、预算降级、无效响应及旧缓存隔离。固定错误注入仍保留“目标语言正确但意思错误”的反例，不把它改成通过。客户端原始证据与备份留在 Git 外。
