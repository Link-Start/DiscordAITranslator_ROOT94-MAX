# Agent Note: 百度凭证按官方字段编辑并兼容旧配置

Status: implemented

## Problem

百度通用文本翻译要求 APP ID 和签名密钥。旧界面把二者合并成一个“API 密钥”输入框，依赖用户理解空格分隔约定；运行时还兼容三段格式，其第三段才是密钥。

## Decision

界面分别编辑 APP ID 和密钥，使用既有防抖和生命周期提交。小型凭证解析模块由设置存储和供应商适配器共享；旧记录只读兼容，首次编辑才写入独立字段。字段缺失与明确清空分开处理，防止旧值恢复或另一半凭证丢失。

完整配置保留派生的旧 `key`，供旧构建读取；未完成配置将其清空。独立字段是新构建的读取依据。供应商仍调用原通用翻译端点，签名算法不变；错误脱敏同时覆盖新字段。

## Alternatives considered

- 仅修改占位符：用户仍需手动拼接，无法分别验证和编辑。
- 每次编辑只保存拼接字符串：首字段为空时无法区分缺少 APP ID 与缺少密钥，也易丢失另一字段。
- 直接删除旧字段：降低回退到旧构建时的可用性，因此保留完整凭证的兼容投影。

## Consequences

读取旧配置不会触发重写；编辑、清空、重新加载和旧三段格式都有合成回归。旧构建修改兼容 `key` 不会更新独立字段，重新回到新构建时应在两个输入框中确认修改。真实账号鉴权仍需用户配置后验证，合成测试不代表服务商接受凭证。
