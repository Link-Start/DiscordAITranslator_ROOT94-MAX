# Agent Note: 显式名称决定与正常跳过分开于失败重试

Status: implemented

## Problem

[批内语境方案](2026-09-17-batch-context-whole-result.md)只向混合句的单词开放名称保留，遗漏名称加版本、百分比、名称列表和独立多词产品名。模型合理保留它们仍可能触发语言或相似度失败。完整不变结果还会经过译文提交，未统一为正常跳过。

## Decision

typed 请求用 `allowNameKeep` 授予显式名称决定的权限，由模型根据片段及可用语境判断，不由单词正则决定名称。只有明确的保留标记才能走此路径，普通原样回显不因此自动通过。完整重组结果逐字等于根原文时，收到消息走既有 skipped 终态；历史主请求、批次修复、单项修复及实时路径一致，清除相应失败快照并保留跳过缓存。

可选语境与许可独立，预算限制仍生效；修复不能突然获得原请求未声明的权限。名称许可启用时，既有修复请求追加固定反馈，明确普通回显与未标记名称不能原样重交；不新增预判或修复次数。原生非 typed 适配器维持既有协议。部分通过不能跳过整条，也不能提交部分译文。当前行为和接口见[功能说明](../../../../docs/product.md)与[供应商说明](../../../../docs/providers.md)。

## Alternatives considered

未继续扩大本地名称正则或维护产品词典：词形无法可靠区分多词名称与普通句子。未把所有 wrong-language 或 too-similar 当成功：会掩盖真实漏译。未新增 AI 二次判定：继续在原有请求内完成，保留当前请求次数上限。

## Consequences

确认无需改动的消息不再进入无意义重试，也不算已翻译。明确名称决定依赖模型语义理解，仍可能误把普通词认作名称；ID、保护与完整性检查不能消除此风险。固定提示词和许可略增输入，无额外预判请求，不宣称零延迟或零误判。既有纯名称兼容启发式保留，旧保留结果需通过当前缓存策略。

公开回归使用合成名称，覆盖单条及历史路径、主请求和修复、旧失败账本清理、普通漏译拒绝和完整消息验收。私人现场文本、供应商响应及部署备份不进入仓库。
