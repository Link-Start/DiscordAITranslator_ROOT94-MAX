# 设计与经验笔记维护规则

- 遵循[笔记生命周期与格式](README.md)，使用 `.agents/templates/` 中的模板。
- 一篇笔记记录一个决策。实现事实变化时更新相关有效笔记；反转决策时另写笔记并明确互相引用。
- 写清问题、证据、实际考虑过的替代方案和最终取舍；不得编造被否决的方案或最初提案日期。
- 标题主题和正文用中文，保留 `Agent Note`、`Status` 和模板要求的英文小节字段，便于结构检查。
- implemented 笔记描述已成立的事实。由 proposed 转入时移除待执行步骤和验收清单，改写为实际决策与影响。
- 部分被替代的笔记继续保持有效并添加链接。只有不再包含独有当前约束的 implemented 笔记才可归档；归档前先把仍有价值的理由保留到后继笔记。rejected 笔记在 Status 行保留拒绝结论。
- 已归档文件和清单中的现有条目不可修改。需要更正或替代时新增有效笔记，不改旧文件字节或哈希；中文化也不改写冻结历史。
- 审查和 CI 使用明确的变更前 Git 基线。`HEAD` 仅是本地未提交工作默认值，新提交不能用自身来证明归档未被修改。
- 检查器只验证结构和冻结历史。审查仍需核实事实、理由保留情况，以及简化证据是否覆盖生产调用者。
