PART 01 · 拆解

删除插件的界面好在哪

值得搬过来的是一套「造界面的规矩」，不是某个页面。

  • 一套颜色令牌。颜色全部取自 Discord 官方主题变量，界面与 Discord 本体融为一体，换主题自动跟随。
  • 一套自绘控件。开关、下拉、密钥框、模型框、分段按钮全部自己画，不依赖会过时的第三方库。
  • 说明藏在 ⓘ 里。设置行只留「名字 + 控件」，解释文字悬停才出现。
  • 标签页替代长页面。每页只讲一件事，左边名字、右边控件。
  • 状态一眼可读。绿点=已配置、蓝紫=生效中、彩色状态行=操作结果、红=危险。

PART 04 · 界面稿

可交互设计稿

这一版的每处改动都对应下面四条 UX 原则；虚线黄框是设计标注，表示「什么条件下才显示」，不是真实控件。

UX 01
句式化
设置读起来像一句话：「收到的消息：从 __ 翻成 __」，而不是四个孤立的下拉。
UX 02
后果前置
要用户选的地方，把代价写在选项上：免费还是耗额度、要不要密钥，选之前就知道。
UX 03
依赖联动
子设置缩进挂在父开关下，父项一关子项变灰——用户永远不会调一个不生效的设置。
UX 04
状态引导
空状态告诉你第一步做什么；配置状态用绿点常驻可见；操作结果留在原地不消失。

现状问题清单（红圈 ①–⑥，证据 = 真机截图 + 源码；状态词序 stale/upstream 已在安装链 S1 修复，不再列为问题）：① 模型行与思考设置行贴排、状态/按钮/高级区 6–8px 内堆叠，分组感缺失；② 三态切换有死路——「跟随上游」下高级区没有强度行，想调强度必须先切「手动设置」再回高级区两跳完成，真机曾出现「跟随上游→手动设置」切换无效（S2 转换链未实施）；③ 验证主动作从模型行漂移到思考区并改名「检测模型」，用户以为旧「验证配置」消失；④ 手动设置下「兼容方式」裸露 OpenAI/DeepSeek/Qwen 品牌枚举，像在选第二套协议；⑤ 思考强度封顶「高」（源码 REASONING_EFFORTS 仅 minimal/low/medium/high，未知档位一律折算成 low 发送），max/xhigh/数值预算无法表达；⑥ 196px 选择器截断「OpenAI Chat Completi…」，3 个选项的下拉还带搜索框。现状视图的选项文案与安装版一致（自动适配/跟随上游/手动设置）；「关闭/开启」三态仅在优化后视图提出。

优化原则与定案（简化裁决版）：动作归位——「验证配置」回到模型行三合一（下拉+获取列表+验证），是唯一主验证动作，下方状态行只被它驱动；自上而下的操作顺序 = 选模型 → 验证 → 选模式 → 选强度。普通路径只有「思考模式」三选一（跟随上游 / 关闭思考·推荐 / 开启思考），开启后才出现「思考强度」，切模式保留上次强度。强度主标签直接显示上游原始值（auto / dynamic (-1) / minimal / low / medium / high / max / xhigh / 数值预算 / Custom…），绝不把 max 与 xhigh 合并成中文档名、未知值不归一；中文解释只在菜单副行与提示；状态句 =「已确认开启思考 · high」这类人话+raw，选项集合按「地址+接口类型+模型」记忆、切模型即时恢复。验证失败只给单一下一步：设置未生效 →「重新验证」（插件内部自动换用其他已知写法）；接口拒绝 →「查看诊断」——用户永远不选 OpenAI/DeepSeek/Qwen 字段族，字段写法与自定义映射全部退为 adapter 内部能力（见 notes 内部架构附录，极端网关的自定义映射只作为诊断/开发者选项概念，本轮不实现）。高级设置仅两项：接口类型（默认自动识别）+ 速度测试（跟随上游隐藏、配置确认后可用）。窄宽 <430 为独立副稿（容器类 .pm-narrow，不用全局 @media），模型行换行后「验证配置」仍完整可见。
